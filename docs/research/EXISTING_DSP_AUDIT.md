# What the shipping ElectroBow actually processes

**Audit baseline** — all paths and line numbers below refer to [leprpht/electro-bow at aa1be375020f81b223171cc8feed52b50dccb7d2](https://github.com/leprpht/electro-bow/tree/aa1be375020f81b223171cc8feed52b50dccb7d2). The current instrument reshapes a pluck and colors its spectrum. Its modes lose energy on every cycle. When the input stops, the only remaining audio is filter memory. Turning up Noise cannot establish a period or supply energy indefinitely.

## What is oscillating?

For each production mode let ω=2πfc/fs, α=sin(ω)/(2Q), b=α/(1+α), A=2cos(ω)/(1+α), B=(α−1)/(1+α). The tick realizes

```text
y[n] = b (x[n] − x[n−2]) + A y[n−1] + B y[n−2].
```

There is genuine recursive feedback. Its conjugate poles have radius sqrt((1−α)/(1+α)) < 1 over the designed range. At 48 kHz the 102 Hz, Q=1.6 mode has an amplitude time constant of about 5 ms (−1/(fs ln r)). It rings briefly at its own pole frequency after an impulse. All input paths to these modes in production are functions of the current crossover outputs and time-varying multipliers. Neither a bow velocity source nor a pitch-tuned return loop feeds them. The output guard, LFO, noise generator and envelope states all have memory, but none closes that loop. A stationary pitched input can therefore sound pitched for as long as it drives the filters. A vanishing input cannot be converted by this path into a stable new note with a player-controlled tail. [Mode and pickup implementation](https://github.com/leprpht/electro-bow/blob/aa1be375020f81b223171cc8feed52b50dccb7d2/rust/dsp/src/instrument/body.rs#L14-L110)

**Interpretation of the noise report.** Multiplication by filtered random modulation makes broadband sidebands that the bright modes can emphasize. The source establishes that mechanism, including its dependence on Noise, Character and low-band energy. It does not establish which parameter, pickup noise, host routing or recording caused the reported listening experience. A dry/factory/noise-zero level-matched capture of the same DI through the identified plugin binary is the discriminating check. Even if noise were inaudible, the present path would still lack sustained bow excitation.

## What the baseline tests establish

At the audit commit, `cargo test --workspace --locked --offline` passed **59 unit and 3 integration tests** in this investigation. No new plugin was built or auditioned. The existing fixtures answer different questions:

- `rust/dsp/src/instrument/tests.rs:46–99,101–160,162–216` checks dial audibility, neutral transparency, 64 control corners, exact partition replay, automation continuity, channel isolation, short tail and superposition with saturation/swell disabled. That last linearity property is specific to the old active model. Keep it on a legacy render or replace its production assertion with monophonic fallback and neutral-path checks.
- `rust/dsp/src/instrument/body.rs:118–141` checks unity center gain and finite modal release. `rust/dsp/src/attack/tests.rs:17–98,128–190` checks swell bypass, reset, linked stereo, decay and repicks. `rust/dsp/src/filter_bank/tests.rs:3–81` checks preparation, scaled cutoffs, sanitation and scratch state. Retain these small regressions.
- `rust/dsp/src/ffi/tests.rs:12–36,142–end` counts thread-local alloc/realloc/dealloc around prepared processing/reset. Extend the production fixture to actually lock a note, hold it and replace it. `rust/dsp/src/signal_path_tests.rs:39–146,239–354,397–524` exercises the older full-path API. Its sustain assertions are not waveguide tests.
- `tests/FilterBankTests.cpp:315–478,479–650` covers the actual processor, tail, controls, bypass, invalid values and state recall. `docs/timbral-instrument.md` records past recorded-guitar and CPU measurements, and an inconclusive FL Studio render. Earlier `docs/final-effect.md`, `docs/rust-dsp.md` and `docs/roadmap-audit.md` cover other development stages. Use the call graph and baseline above to interpret those results. [Historical instrument measurements](../timbral-instrument.md)

The target reuses the stream shell, crossover, direct Attack, body modes and final protection. It adds a source of mechanical work and a control path to keep that source tuned.
